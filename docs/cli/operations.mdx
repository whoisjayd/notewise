## Runtime inspection

### `yt-study info [URL]`

Without a URL, prints runtime environment details. With a URL, inspects metadata without generating notes.

```bash
yt-study info
yt-study info "https://youtube.com/watch?v=VIDEO_ID"
yt-study info "https://youtube.com/playlist?list=PLAYLIST_ID"
```

### `yt-study doctor`

Runs non-destructive health checks for config, cache database, logs, and key model requirements.

```bash
yt-study doctor
```

### `yt-study version`

```bash
yt-study version
```

## Metrics and history

### `yt-study stats`

```bash
yt-study stats                                       # all-time totals
yt-study stats --model gemini/gemini-2.5-flash       # filter by model
yt-study stats --since 7                             # last 7 days
yt-study stats --since 30d                           # last 30 days
```

### `yt-study history`

```bash
yt-study history               # last 10 processed videos
yt-study history --limit 25
```

## Cache commands

### `yt-study cache`

<Tabs>
  <Tab title="Flag mode">
    ```bash
    yt-study cache             # show database info
    yt-study cache --info
    yt-study cache --show VIDEO_ID
    yt-study cache --clear --yes
    yt-study cache --prune 30
    ```
  </Tab>
  <Tab title="Subcommand mode">
    ```bash
    yt-study cache show VIDEO_ID
    yt-study cache clear --yes
    yt-study cache prune --older-than 14
    ```
  </Tab>
</Tabs>

<Warning>
  `cache --clear` deletes all local processing history, transcript cache entries, and export records from the SQLite database. Generated note files on disk are **not** affected.
</Warning>

## Log commands

### `yt-study logs`

```bash
yt-study logs              # list recent log files
yt-study logs --tail 80    # tail the latest log
yt-study logs --open       # open log directory in file manager
```

### `yt-study logs clean`

```bash
yt-study logs clean                    # remove logs older than 7 days
yt-study logs clean --older-than 30
yt-study logs clean --all              # remove all inactive logs
```

---

## Command behavior notes

- `cache` allows one action at a time (`--info`, `--show`, `--clear`, or `--prune`).
- `--yes` is only valid with `cache --clear`.
- All operations commands avoid network-heavy processing except `info URL`.

<AccordionGroup>
  <Accordion title="When should I use doctor vs info?">
    Use `doctor` for environment and health diagnostics. Use `info URL` for metadata inspection of a specific video or playlist source.
  </Accordion>
  <Accordion title="Why are there two forms for cache commands?">
    Flag mode and subcommand mode are equivalent — pick one style for scripts and team consistency.
  </Accordion>
</AccordionGroup>
