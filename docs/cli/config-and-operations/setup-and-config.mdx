### `notewise setup`

Run the interactive setup wizard. It uses a bundled LiteLLM model catalog for fast startup and falls back to live metadata only when needed. Prompts for your LLM provider and writes `~/.notewise/config.env`. API-key providers ask for the matching key; OAuth/device-flow providers such as ChatGPT subscription and GitHub Copilot skip API-key storage and offer to run OAuth login immediately.

```bash
notewise setup
notewise setup --force    # re-run even when config already exists
notewise setup --show     # display current config and exit
```

| Option | Description |
| --- | --- |
| `--force` / `-f` | Re-run wizard even when config already exists |
| `--show` | Display current config and exit |

### `notewise auth login`

Run LiteLLM's OAuth/device-flow login for subscription-backed providers without writing API keys to notewise config. This command makes a tiny test request so LiteLLM can create or refresh the provider token before you run `notewise process`.

```bash
notewise auth login                 # pick provider interactively
notewise auth login chatgpt
notewise auth login github_copilot
```

Use this in an interactive terminal so LiteLLM can show the device code or browser URL. Codex subscription users should run `notewise auth login chatgpt`; `notewise auth login codex` remains a compatibility alias for ChatGPT subscription login.

notewise defaults provider token storage to `$NOTEWISE_HOME/oauth/chatgpt` and `$NOTEWISE_HOME/oauth/github_copilot` (or `~/.notewise/oauth/...` when `NOTEWISE_HOME` is unset); override those locations with `CHATGPT_TOKEN_DIR` or `GITHUB_COPILOT_TOKEN_DIR` when needed.

After login, run with the provider model normally:

```bash
notewise process "URL" --model chatgpt/gpt-5.2
notewise process "URL" --model github_copilot/gpt-5-mini
```

### `notewise config`

Show the fully resolved runtime configuration. API keys are masked.

```bash
notewise config
```

---

### `notewise config-path`

Print the config file path and whether it exists.

```bash
notewise config-path
```

---

### `notewise edit-config`

Open `config.env` in your `$EDITOR`. On Windows, Notepad is used when `EDITOR` is not set.

```bash
notewise edit-config
```

---

### Key files

| File | Purpose |
| --- | --- |
| `~/.notewise/config.env` | Primary config file |
| `~/.notewise/.notewise_cache.db` | SQLite cache |
| `~/.notewise/logs/` | Session log files |

Override the state directory:

```bash
export NOTEWISE_HOME=/custom/path
```

### Common setup issues

<AccordionGroup>
  <Accordion title="Setup says config already exists">
    Re-run with force:

    ```bash
    notewise setup --force
    ```
  </Accordion>

  <Accordion title="Need to verify which config file is active">
    ```bash
    notewise config-path
    ```

    If `NOTEWISE_HOME` is set, notewise resolves config from that directory.
  </Accordion>

  <Accordion title="API key looks set but calls still fail">
    Confirm model/key pairing in resolved config:

    ```bash
    notewise config
    ```

    Verify `DEFAULT_MODEL` and the matching provider API key are both present. For OAuth providers, run once in an interactive terminal so LiteLLM can show the device code.
  </Accordion>

  <Accordion title="OAuth provider works locally but fails in CI">
    OAuth login must be completed before headless runs. Run `notewise auth login chatgpt` or `notewise auth login github_copilot` interactively, then make sure the same `NOTEWISE_HOME`, `CHATGPT_TOKEN_DIR`, or `GITHUB_COPILOT_TOKEN_DIR` is available to the automation environment.
  </Accordion>
</AccordionGroup>
