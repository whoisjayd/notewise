## Processing a playlist

<Tabs>
  <Tab title="Playlist URL">
    ```bash
    yt-study process "https://youtube.com/playlist?list=PLAYLIST_ID"
    ```
  </Tab>
  <Tab title="Watch + list URL">
    ```bash
    yt-study process "https://www.youtube.com/watch?v=ID&list=PLxxxxxx"
    ```
  </Tab>
  <Tab title="Bare playlist ID">
    ```bash
    yt-study process PLxxxxxx
    ```
  </Tab>
</Tabs>

yt-study will:
1. Fetch the full playlist and enumerate all video IDs
2. Process videos concurrently (up to `MAX_CONCURRENT_VIDEOS`, default 5)
3. Write each video's notes as top-level Markdown files in the output directory

---

## Batch file processing

Create a plain text file with one URL per line:

```text
# my-course.txt
https://youtube.com/watch?v=VIDEO_ID_1
https://youtube.com/watch?v=VIDEO_ID_2
https://youtube.com/playlist?list=PLxxxxxx
```

<Note>
  Blank lines and lines starting with `#` are ignored. Each entry can be a video URL, playlist URL, or bare ID.
</Note>

Then pass the file to `process`:

```bash
yt-study process my-course.txt
yt-study process ~/course/urls.txt -o ~/course/notes
```

## Tuning concurrency

```bash
# In ~/.yt-study/config.env:
MAX_CONCURRENT_VIDEOS=10

# Or per run:
MAX_CONCURRENT_VIDEOS=2 yt-study process my-course.txt
```

<Warning>
  Higher concurrency processes faster but increases API costs per unit time and may hit YouTube rate limits. Use `YOUTUBE_REQUESTS_PER_MINUTE` to stay within limits.
</Warning>

## Resuming an interrupted run

By default, yt-study skips videos already in cache with existing output targets — making re-runs safe:

```bash
yt-study process my-course.txt   # run 1 — processes all
yt-study process my-course.txt   # run 2 — skips all (output exists)
```

Use `--force` to re-process everything:

```bash
yt-study process my-course.txt --force
```

## Useful batch flags

```bash
# Generate quizzes for every video
yt-study process my-course.txt --quiz

# Non-interactive for cron / CI
yt-study process my-course.txt --no-ui 2>&1 | tee run.log

# Use a specific model for the whole batch
yt-study process my-course.txt --model gpt-4o

# High concurrency for large batches
MAX_CONCURRENT_VIDEOS=10 yt-study process urls.txt --no-ui
```

<AccordionGroup>
  <Accordion title="What exactly gets skipped on re-run?">
    A video is skipped when cache state indicates prior processing and expected output targets already exist on disk.
  </Accordion>
  <Accordion title="When should I lower concurrency?">
    Lower `MAX_CONCURRENT_VIDEOS` when running on constrained hardware or when you are approaching provider or YouTube rate limits.
  </Accordion>
</AccordionGroup>
