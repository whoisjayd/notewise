## The cache

yt-study stores transcripts, video metadata, and run statistics in a local SQLite database:

```text
~/.yt-study/.yt_study_cache.db
```

### What the cache does

| Function | Description |
| --- | --- |
| **Skip processed videos** | Tells the pipeline what it has already seen |
| **Stats & history** | `stats` and `history` commands read from it |
| **Run telemetry** | Token, cost, and timing records stored per run |

### Cache commands

<AccordionGroup>
  <Accordion title="Inspect" icon="search" defaultOpen>
    ```bash
    yt-study cache           # database metadata and entry counts
    yt-study cache --info    # same as above, explicit
    yt-study cache --show VIDEO_ID
    yt-study cache show VIDEO_ID
    ```
  </Accordion>

  <Accordion title="Clear" icon="trash-2">
    ```bash
    yt-study cache --clear          # prompts for confirmation
    yt-study cache --clear --yes    # skip confirmation
    yt-study cache clear --yes
    ```

    <Warning>
      `cache --clear` deletes all local processing history, transcript cache entries, and export records from the SQLite database. Generated note files on disk are **not** affected.
    </Warning>
  </Accordion>

  <Accordion title="Prune old entries" icon="scissors">
    ```bash
    yt-study cache --prune 30              # entries older than 30 days
    yt-study cache prune --older-than 14   # entries older than 14 days
    ```
  </Accordion>
</AccordionGroup>

### Usage statistics

```bash
yt-study stats                                       # all-time totals
yt-study stats --model gemini/gemini-2.5-flash       # filter by model
yt-study stats --since 7                             # last 7 days
yt-study stats --since 30d                           # last 30 days
```

### Processing history

```bash
yt-study history               # last 10 processed videos
yt-study history --limit 25    # last 25
```

## Session logs

Every `process` run writes a structured log to:

```text
~/.yt-study/logs/yt-study-YYYYMMDD-HHMMSS.log
```

Logs use [structlog](https://www.structlog.org/) JSON format. API keys and sensitive values are automatically redacted.

### View logs

```bash
yt-study logs              # list recent log files
yt-study logs --tail 50    # tail the latest log (last 50 lines)
yt-study logs --open       # open the log directory in your file manager
```

### Clean up logs

```bash
yt-study logs clean                    # remove logs older than 7 days (default)
yt-study logs clean --older-than 30    # remove logs older than 30 days
yt-study logs clean --all              # remove all inactive log files
```

## Health check

Run a non-destructive check to verify config, cache, and logs are all in order:

```bash
yt-study doctor
```

This checks:
- `~/.yt-study/config.env` exists and is readable
- SQLite cache can be opened
- Log directory is writable
- Configured model's API key appears to be set
